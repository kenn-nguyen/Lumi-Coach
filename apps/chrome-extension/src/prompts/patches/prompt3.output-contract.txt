- Do not output markdown fences.
- Do not output commentary, analysis, or text before or after the JSON object.

- Return exactly one JSON object matching the schema below.
- Do not add extra top-level keys.
- If a field is unknown, use the schema’s empty value (`""`, `[]`, `{}`, or `null` as appropriate).

Additional schema rules:
- `resume_data` is required.
- `generation_feedback` is optional but recommended when there are concise user-facing notes worth showing.
- `flex_notes` is optional and must be a string or null; use `""` when unused.
- Use `flex_notes` only for small non-critical writer notes needed by future prompt variants.
- Do not place `flex_notes` inside `resume_data`; it is prompt metadata only.
- Do not use the em dash character `—` anywhere in the JSON output. Use a normal hyphen `-` instead.
- `resume_data.summary` should be one short paragraph, preferably 1 sentence, at most 2 short sentences.
- For resume bullet arrays such as experience bullets, project bullets, and custom-section bullets, do not end items with a period `.`.
- If `generation_feedback` is present:
  - `summary` should be one short sentence
  - `pros`, `cons`, and `caveats` should contain short bullet-style strings only
  - keep every item concise and user-facing
- If there is no meaningful feedback, you may omit `generation_feedback` or return it with empty values.
- `workExperience[].context` is optional and must be a string or null when present.
- Use `null` or omit `workExperience[].context` when no supported company context exists.
- Do not put company context inside `workExperience[].description`.
- `workExperience[].website` is optional and must be a string or null when present.
- Preserve source experience websites; do not invent role, company, case-study, or employer URLs.
- Valid `sectionType` values are:
  - `personalInfo`
  - `text`
  - `itemList`
  - `stringList`
- In `sectionMeta`, `personalInfo` is a built-in section and should normally remain first if present.
- `sectionMeta.key` should match either a built-in field name such as `summary`, `workExperience`, `education`, `personalProjects`, `additional`, or a matching key inside `customSections`.
- For built-in sections, preserve existing `id`, `key`, `displayName`, `sectionType`, `isDefault`, `isVisible`, and `order` whenever they already exist.
- For custom sections, preserve existing keys and IDs whenever they already exist.
- When the current resume already includes `sectionMeta`, preserve its section ordering and display names by default.
- Do not reorder built-in sections into a preferred default sequence when the current resume already provides a valid sequence.
- Do not rename built-in sections such as `Experience`, `Education`, or `Projects` unless the current resume already uses a different label or the prompt explicitly requires it.
- `customSections` entries must follow these rules:
  - if `sectionType` is `text`, use `text` and leave `items` and `strings` null or absent
  - if `sectionType` is `itemList`, use `items` and leave `text` and `strings` null or absent
  - if `sectionType` is `stringList`, use `strings` and leave `text` and `items` null or absent
- Each `itemList` entry inside `customSections` should follow this shape:
  {
    "id": 1,
    "title": "",
    "subtitle": null,
    "location": null,
    "years": "",
    "description": []
  }
- Do not create new custom sections unless they are already present in the current resume or clearly required by supported source material.
- If custom sections are absent from the current resume, prefer leaving `customSections` as `{}`.
