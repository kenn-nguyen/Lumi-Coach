Output contract:
- Return one valid JSON object only
- There are exactly two valid output shapes:
  1. Non-resume rejection object
  2. Resume extraction object with `resume_data`
- Do not include `generation_feedback`
- Do not include any keys outside `resume_data` and optional top-level `flex_notes` unless returning the explicit non-resume rejection object
- Use integer `id` values for `workExperience`, `education`, and `personalProjects`
- Use `null` only where the schema allows nullable strings
- Use empty arrays or empty strings instead of inventing content

Shape 1 - non-resume rejection:
- If the uploaded input does not contain enough direct resume facts to populate at least one meaningful resume area, return this exact JSON object and no other keys:
{
  "error": "not_resume",
  "message": "The uploaded file does not contain enough resume information."
}
- Do not return an empty ResumeData template for non-resume input.

Shape 2 - Resume extraction object:
- Only use this shape when the input is resume-like.
- Required top-level keys:
{
  "resume_data": {
    "personalInfo": {
      "name": "",
      "title": "",
      "customTagline": null,
      "email": "",
      "phone": "",
      "location": "",
      "website": null,
      "linkedin": null,
      "github": null
    },
    "summary": "",
    "workExperience": [],
    "education": [],
    "personalProjects": [],
    "additional": {
      "technicalSkills": [],
      "languages": [],
      "certificationsTraining": [],
      "awards": []
    },
    "sectionMeta": [],
    "customSections": {}
  },
  "flex_notes": ""
}

Validation notes:
- `resume_data` is required in Shape 2
- `flex_notes` is optional as a top-level prompt note and must be a string or null; use `""` when unused
- Do not place `flex_notes` inside `resume_data`; it is prompt metadata only
- Do not include `flex_notes` in the non-resume rejection object
- `workExperience[].description` must be an array of strings
- `workExperience[].context` may be a string or null and is optional
- `workExperience[].website` may be a string or null and is optional
- `personalProjects[].description` must be an array of strings
- `education[].description` must be a string or null
- `customSections` must be an object, even when empty
- `sectionMeta` must be a full array, not omitted
- Every `sectionMeta[]` item must be an object with:
  - string `id`
  - string `key`
  - string `displayName`
  - string `sectionType` using only `personalInfo`, `text`, `itemList`, or `stringList`
  - boolean `isDefault`
  - boolean `isVisible`
  - integer `order`
- Built-in sections should normally use matching `id` and `key` values, such as `summary` / `summary`
- Do not return an empty schema template when the Markdown contains real resume content
