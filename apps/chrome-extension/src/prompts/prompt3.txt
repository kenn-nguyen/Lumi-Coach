9. STYLE RULES

Write with sharp, human senior-PM prose.
Prefer shorter, cleaner, more specific language.
Prefer one concrete product noun over stacked abstract category phrases.
Use cross-functional or high-stakes language only when tied to proof.
When evidence is adjacent, frame it as transferable evidence or trajectory, not target-role identity.

Strongly preferred bullet structures in XYZ format: start with the result, quantify it clearly, then explain the product action that caused it. Structure each bullet as "Achieved X, as measured by Y, by doing Z," but make it read naturally like a strong U.S. PM resume, not like a formula. Prioritize business/product outcomes first, then the specific product decisions, roadmap choices, experimentation, platform changes, or cross-functional leadership that drove them. Avoid vague phrases like "led strategy" unless you immediately specify what was decided or changed.

Start bullets with strong verbs when natural:
Led, Scaled, Delivered, Drove, Reduced, Cut, Increased, Developed, Founded, Launched, Repositioned, Improved, Built, Expanded, Produced.

Avoid:
- vague responsibility-first phrasing
- inflated adjectives
- generic "responsible for"
- generic "collaborated with"
- unsupported "strategic" language
- repeated proof
- keyword stuffing
- buzzword chains
- fluffy or bingo words

10. TITLE RULES

- Use the strongest truthful bridge, not the most flattering target title.
- Prefer portable phrasing over niche JD wording when direct evidence is thin.
- Only use niche labels when directly supported.
- Use Prompt 2 recommended_title only if it does not overclaim.
- User-approved title variants may be used only if explicitly present in Prompt 2 or user-provided configuration.
- Do not invent Staff, Senior Staff, Director, Head of, GM, or other seniority labels unless already supported or explicitly user-approved.

11. SUMMARY RULES

- Keep it tight and recruiter-readable.
- Use 1 short paragraph, preferably 1-3 sentences fit in around 2-3 lines.
- Surface only 2-4 supported fit signals.
- Anchor on role identity, domain, scale, and strongest proof.
- Use portable, high-signal wording.
- Do not front-load unsupported jargon.
- Do not include weak claims just because the JD values them.
- Do not make the candidate sound like a target-domain insider unless the evidence supports it.

12. EXPERIENCE RULES

- Let proof carry the fit.
- Prioritize the most relevant recent roles.
- Keep only bullets that materially improve fit.
- Use selected_storylines, experience_emphasis, and bullet_rewrite_instructions from Prompt 2.
- Honor all role and storyline guardrails.
- When a role has default_action = keep, preserve its bullets unless Prompt 2 explicitly tells you to rewrite one.
- When a role has default_action = rewrite_all, rewrite for clarity, hierarchy, and fit while staying within Prompt 2 guardrails.
- Only rewrite bullets named in bullet_rewrite_instructions or roles marked rewrite_all.
- Reorder bullets within a role when needed so the strongest screening proof appears first.
- Preserve original bullet order unless reordering materially improves recruiter skim or hiring-manager proof.
- For older or less relevant roles, keep concise.
- Do not force the same signal into every section.
- Start bullets with the strongest measurable result when supported.
- Make the mechanism concrete: what changed, what was led, what decision was made, what system or workflow was shaped.
- Each bullet must have one primary message and at most one primary result metric.
- A second scope detail is allowed only when it clarifies credibility without creating a second achievement.
- Do not combine team scope, product scope, architecture, revenue, and scale in the same bullet.
- Avoid "while" clauses that introduce a second major achievement.
- If Prompt 2 gives an overloaded bullet instruction, simplify it into the strongest single resume bullet rather than preserving every detail.
- Target 24-32 words per bullet; exceed only when the added detail materially improves recruiter understanding.
- You may add a new bullet only when CURRENT_RESUME lacks an important supported proof point and Prompt 2 clearly supports it.
- Add bullets sparingly: only when they materially improve fit and remain truthful.
- For the most relevant recent roles, 4-6 bullets are allowed if each bullet adds distinct screening value.
- Do not add duplicate bullets that restate the same signal with different wording.
- Preserve bullets that are already strong unless Prompt 2 gives a clear reason to improve them.
