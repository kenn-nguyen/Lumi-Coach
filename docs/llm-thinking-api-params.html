LLM Thinking / Reasoning — API Parameter Reference

Exact field names, nesting, and valid values for 4 providers. Sourced from official docs, June 2026.

GOOGLE

Gemini 2.5 Flash & Pro

gemini-2.5-flash  ·  gemini-2.5-pro
// REST body — generateContent
{
  "contents": [...],
  "generationConfig": {
    "thinkingConfig": {
      "thinkingBudget": 1024,
      "includeThoughts": true
    }
  }
}
  • thinkingBudget — integer token cap for internal reasoning
  • Flash range: 0–24,576  |  0 = disable thinking  |  -1 = dynamic (model decides)
  • Pro range: 128–32,768  |  cannot be disabled (no 0)  |  -1 = dynamic
  • includeThoughts — when true, response parts contain thought summaries (with thought: true flag); not raw thought tokens
  • Do not mix thinkingLevel (Gemini 3.x) with thinkingBudget (2.5.x)
Default for both models is -1 (dynamic). Setting thinkingBudget: 0 on Pro returns an error.
ANTHROPIC

Claude — extended thinking

claude-sonnet-4-6  ·  claude-opus-4-5
// Sonnet 4.6 — preferred: effort via output_config
{
  "model": "claude-sonnet-4-6",
  "max_tokens": 16000,
  "output_config": {
    "effort": "high"
  },
  "thinking": { "type": "adaptive" },
  "messages": [...]
}

// Older explicit style (deprecated on 4.6+)
{
  "thinking": {
    "type": "enabled",
    "budget_tokens": 10000
  }
}
  • budget_tokens must be less than max_tokens; no hard-coded min, but must be > 0
  • Recommended max budget: ~32k tokens (higher rarely improves quality)
  • effort valid values: low, medium, high (default), max
  • Sonnet 4.6 + Opus 4.6: use output_config.effort + thinking: {type: "adaptive"}
  • Older models (Opus 4.5): use thinking: {type: "enabled", budget_tokens: N}
Deprecated on Sonnet 4.6: budget_tokens still accepted but will be removed. Use output_config.effort instead.
DEEPSEEK

DeepSeek thinking mode

deepseek-v4-pro  ·  deepseek-v4-flash
// Native DeepSeek REST API
{
  "model": "deepseek-v4-pro",
  "messages": [...],
  "thinking": {
    "type": "enabled",
    "reasoning_effort": "high"
  }
}

// Via OpenAI SDK (extra_body)
{
  "model": "deepseek-v4-pro",
  "reasoning_effort": "high",
  "extra_body": {
    "thinking": { "type": "enabled" }
  }
}
  • thinking.type: "enabled" | "disabled" — defaults to enabled
  • reasoning_effort: "high" | "max" — low/medium map to high; xhigh maps to max
  • No top-level enable_thinking boolean — that param does not exist
  • Response includes reasoning_content field with CoT text
  • Temperature / top_p / penalties are silently ignored in thinking mode
deepseek-reasoner retiring July 24, 2026 — migrate to deepseek-v4-pro with thinking: {type: "enabled"}
OPENAI

OpenAI reasoning models

gpt-5.4  ·  gpt-5.4-mini  ·  o3  ·  o3-mini
// Responses API (recommended)
{
  "model": "gpt-5.4",
  "input": "Your prompt",
  "reasoning": {
    "effort": "high"
  }
}

// Chat Completions API (legacy-compatible)
{
  "model": "gpt-5.4",
  "reasoning_effort": "medium",
  "messages": [...]
}
  • Responses API: nested as reasoning: { effort: "..." }
  • Chat Completions API: top-level reasoning_effort field
  • Valid values: none, low, medium (default), high, xhigh
  • gpt-5.5+ also supports minimal; older o-series may not support all levels — check the model page
  • Higher effort = more reasoning tokens billed; xhigh can cost 3–5× vs low
Two APIs, two field structures. Responses API: reasoning.effort. Chat Completions: top-level reasoning_effort.
